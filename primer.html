00The name

Data Cloud was renamed “Data 360” at Dreamforce 2025, announced 14 October 2025 and folded under the Agentforce 360 umbrella. The CDP capabilities did not change with the rebrand. The positioning did — from “customer data platform” to “the live context layer that grounds AI agents.”

It is the sixth name for the same lineage. When reading anything written before October 2025, substitute mentally:

EraName
~2020Customer 360 Audiences
~2021Salesforce CDP / Marketing Cloud CDP
2022Salesforce Genie
2023–2025Salesforce Data Cloud
Oct 2025 →Data 360

Practical consequence: docs, URLs, Trailhead badges and the certification are mid-migration. The credential is now the Salesforce Certified Data 360 Consultant. Both terms still appear in the product UI, and the API namespace kept its data-cloud paths.

01One-sentence mental model

Hold on to this

Data 360 is a Hyper-powered lakehouse bolted onto the Salesforce platform that ingests or federates data from anywhere, maps it into a shared canonical schema, resolves identities into unified profiles, then makes that unified data actionable inside Salesforce — segments, activations, agent grounding, Flow, Tableau.

The part people underestimate: it is not a warehouse you query for reporting. It is an activation layer. If the goal is BI, the answer is Snowflake, Databricks or BigQuery — and Data 360 can now read those in place rather than copying them (§06).

Harmonization

Standardizing naming and formats so fields from five different systems that all describe a person land in the same Individual DMO, and five that describe a company land in Account. Salesforce ships 89 standard DMOs as the Customer 360 Data Model; you extend with custom DMOs where the standard model doesn't reach.

Hard requirement that blocks you immediately: for a Profile or Other DMO you must map its primary key field — without it the mapping will not save. For an Engagement DMO you must map both required fields, because engagement data is time-based by nature.

Data bundles are Salesforce-authored data stream definitions that arrive pre-mapped to DMOs — deploy one and the mapping is done, then customize. Reach for these before hand-mapping anything standard.

Category drives capability

CategoryMeaningTypical DMO
ProfileWho someone is — one row per entityIndividual, Account, Contact Point Email
EngagementSomething that happened at a point in time — requires an event timestampEmail Engagement, Web Engagement, Order
OtherReference and lookup dataProduct, Price Book
Early mistake

Getting the category wrong is the classic first stumble. Identity resolution runs on Profile or Other type streams — an Engagement DLO cannot be mapped to a Profile DMO, and if the category is incompatible Salesforce simply won't show the object in the selector. Conversely, time-windowed segment criteria (“opened an email in the last 30 days”) need the event timestamp that only Engagement data carries. Fixing either later means remapping.

Data Spaces partition all of the above — by brand, region, or legal boundary — inside a single org. They are a priced add-on, not free tenancy.

04Identity resolution

The heart of the product. Two rule types live inside one ruleset:

  • Match rules — which records are the same person? Each rule pairs a field with a match method (Exact, Fuzzy, normalized variants). Every criterion inside a single rule must be satisfied for a link; multiple rules OR together.
  • Reconciliation rules — when linked records disagree, which value wins? Most Recent, Most Frequent, Source Priority, and so on.

Match logic is AND within a rule, OR across rules. A realistic ruleset reads: fuzzy first name AND exact normalized address — OR — fuzzy first name AND exact party identifier.

The output is the Unified Individual, plus unified link objects. Two documented limits worth knowing before you design: you can create up to two identity resolution rulesets per DMO, and unified profiles appear within 24 hours of first publishing a ruleset — so it is not an instant feedback loop.

Critical property

Identity resolution never deletes or overwrites source data. It builds a linkage layer. A unified profile always traces back to its contributing source records, and a ruleset can be changed and re-run.

Design guidance that saves pain

  • Start narrow and precise — exact email, exact phone — then loosen. An over-broad fuzzy name-plus-city rule collapses distinct humans into one profile, and it becomes very visible the moment marketing sends.
  • Every match rule you add costs credits on every run.
  • Party Identification and Contact Point DMOs usually make better match anchors than fields hanging directly off Individual.

06Zero Copy — the structural shift

The biggest change of the last two years. Rather than ingesting, Data 360 federates: it queries Snowflake, Databricks, BigQuery or Redshift in place and materializes nothing.

  • Data stays in the warehouse; governance stays with the warehouse team.
  • Salesforce reports 32 trillion records ingested in Q3 FY2026, 15 trillion of it through zero-copy connectors — up 341% year over year. ⚠ vendor figure
  • The cost profile differs sharply: commonly cited as ~70 credits per million records for federated queries against ~2,000 for classic batch pipelines. ⚠ verify against your rate sheet
  • It runs both ways — Data Sharing lets the warehouse read Data 360 objects back.
The trade-off

Query latency now depends on their warehouse, and every federated query is a live cost on the warehouse side too. Federation doesn't remove the bill, it moves it — and it moves it to a team that may not have agreed to it.

Also in this family now: unstructured connectors for Google Drive and SharePoint, and Clean Rooms for multi-party collaboration without exposing raw data.

07Unstructured data, vectors, agent grounding

This is where Data 360 stops being a CDP and becomes AI infrastructure.

  • Ingest unstructured content — PDFs, transcripts, docs, web pages, chat logs — then chunk, embed, and land it in a search index.
  • Native keyword, vector and hybrid indexing. Hybrid combines semantic recall with keyword precision.
  • Hyper runs ensemble queries across structured, keyword and vector indexes in a single call — the real differentiator against bolting a standalone vector database next to the CRM.
  • Consumed by Agentforce for RAG grounding and agent memory, plus prompt templates, Flow and Tableau.
  • Intelligent Context is the layer explicitly connecting structured records to unstructured sources; Tableau Semantics supplies shared metric definitions so “active customer” means one thing everywhere.
“Why not just use a vector DB?”

Identity. Data 360 grounds retrieval in a resolved customer profile with entitlements and consent attached. A standalone vector store retrieves text; it has no idea whose text it is or whether you're allowed to use it.

08The cost model

Consumption-based, in three buckets:

  1. Credits — ingest, transform, identity resolution, insights, segmentation, activation, queries
  2. Storage — per terabyte per month, billed separately
  3. Premium add-ons — Data Spaces, Real-Time Profiles and similar, at fixed cost

Salesforce's documented formula is exact, and worth memorising because it is the whole model:

Credit formula

credits = (d ÷ u) × m

d = total data processed · u = unit, which is 1 million for every usage type · m = the multiplier for that usage type, published in the rate card.

Salesforce groups billable usage into six categories. Learn these rather than a list of numbers — the categories are stable, the multipliers are not:

CategoryCovers
ConnectBatch and streaming pipelines, data sharing, federation
Harmonize & UnifyData transforms, profile unification
Analyze & PredictCalculated insights, inferences
ActData queries, streaming actions
Segment & ActivateSegment processing, batch and streaming activation
Real-Time ProcessingReal-time profiles and APIs, end to end
Two rules that are documented, unlike the rates

Profile unification carries the highest rate multiplier of any usage type. That single fact should drive your design more than any other: ingest only active profiles, and don't re-run rulesets casually.

Streaming consumes more credits than batch for the equivalent work. Reach for real-time only where the use case genuinely needs it.

Specific multipliers circulate widely in blog posts — Calculated Insights at 15, segment rows at 20, batch activation at 10, zero-copy federation around 70 against ~2,000 for classic batch pipelines. Treat every one of those as unverified. ⚠ Salesforce publishes multipliers only in the rate card, Trailhead's own m=15 example is explicitly labelled illustrative, and the rates move between releases. Pull the current rate card before you put a number in front of anyone.

Where budgets actually die

  • A Calculated Insight scheduled hourly that could run daily — twenty-four times the bill for the same answer.
  • Segments that re-process the full profile base every run instead of a filtered subset.
  • Over-broad identity resolution rulesets re-running across everything.
  • Ingesting data you never activate: storage plus ingest, zero return.
Mitigation pattern

Use a Data Cloud-triggered Flow, or a cheap Calculated Insight, as a gate — so expensive segment and insight runs only fire when the underlying data actually changed.

09Common misconceptions

BeliefReality
“It's a data warehouse”It's an activation layer. Reporting belongs in the warehouse — federate to it
“It's Marketing Cloud's CDP”It's platform-wide: Sales, Service, Agentforce, Tableau, Flow
“Identity resolution merges records”It links them. Sources are never modified
“Ingest everything, decide later”Every stage is metered. Ingest against a named use case or don't ingest
“DMO mapping is one-time setup”It's the core ongoing design surface, and where data quality is won or lost
“Zero Copy is free”It shifts cost to the warehouse and adds a latency dependency

11The 20% that gets you 80%

  1. DLO is raw, DMO is canonical — and the mapping between them is the job.
  2. Identity resolution is match rules plus reconciliation rules — who is the same, then which value wins. Sources are never mutated.
  3. Everything is metered per operation per million rows. Design for refresh frequency, not just correctness.
  4. Zero Copy is the default posture for warehouse data. Ingest only what you will activate.
  5. Its real job in 2026 is grounding Agentforce in resolved, consented customer context.
